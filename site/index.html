Quickstart

Dry-run first. Real run second. Keep the first SSH session open until a second login works.

git clone https://github.com/mohamedtaqysalmi/server-bootstrap.git
cd server-bootstrap
sudo BOOTSTRAP_SSH_PUBKEY="$(cat ~/.ssh/id_ed25519.pub)" ./bootstrap.sh --dry-run
sudo BOOTSTRAP_SSH_PUBKEY="$(cat ~/.ssh/id_ed25519.pub)" BOOTSTRAP_CONFIRM_SSH=1 ./bootstrap.sh

What this does NOT secure

  • Application bugs and broken auth in your own code
  • Compromised apt mirrors or Docker images
  • Cloud security groups (UFW is only on the host)
  • Secrets management, backups, or full IDS
  • Kernel/sysctl hardening beyond the listed steps

How I built it

  1. Plain bash over Ansible so a reader can audit every command without a control node.
  2. SSH change is last, warned, confirmed, and checked with sshd -T.
  3. Caddy instead of Nginx+certbot for short automatic HTTPS config.
  4. Container tests assert dry-run is a no-op and a second real run makes no changes.

Limits

CI does not reload a live sshd or enable UFW on a real NIC. Those paths need a throwaway VPS. Let's Encrypt needs a public DNS name pointing at the host.
