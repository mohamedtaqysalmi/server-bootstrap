server-bootstrap

Harden a fresh Ubuntu VPS without guessing the order.

Idempotent bash steps with a real dry-run. SSH keys-only lands last, after a lockout warning you have to acknowledge.

Steps and why they exist

Each step names the failure mode it reduces. Re-run the script any time; finished work prints ok and changes nothing.

  1. user

    Stop day-to-day work as root so a mistake or stolen session is not the whole machine.

  2. swap

    Give a small VPS a pressure valve so the OOM killer is less likely to kill services.

  3. unattended-upgrades

    Patch known vulnerabilities even when nobody logs in to run apt.

  4. fail2ban

    Slow down password-guessing bots hammering SSH.

  5. log-rotation

    Cap journal growth so logs cannot fill the disk and take the box down.

  6. ufw

    Default-deny inbound traffic; allow SSH, HTTP and HTTPS on purpose.

  7. docker

    Provide an isolated runtime and bound container log size.

  8. proxy

    Terminate TLS with Caddy (default) or Nginx+certbot so apps are not exposed raw.

  9. monitoring

    Optional node exporter so CPU, memory and disk pressure are visible before outage.

  10. ssh

    Keys-only, no root login — applied last, after verify warning, so you do not lock yourself out.

Try it

./bootstrap.sh --list
sudo ./bootstrap.sh --dry-run
sudo BOOTSTRAP_SSH_PUBKEY="$(cat ~/.ssh/id_ed25519.pub)" ./bootstrap.sh
